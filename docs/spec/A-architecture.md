## PART A — ARCHITECTURE: BUILD AN "ODOO-CLASS" METADATA ENGINE, NOT 276 HAND-MADE PAGES

Odoo's UI is generated from metadata: **models → fields**, **views (XML archs) → generic renderers**, **actions → the thing a menu opens**, **menus → navbar**. Reproducing 276 screens by hand-coding React pages would be impossible to keep consistent. You must therefore build the same engine and then feed it the metadata in Parts E–H. This is the only way to satisfy "every option, dynamic, consistent, reliable".

### A-2. The metadata registry (`packages/engine/registry/`)

Implement TypeScript types that mirror Odoo exactly, then load Parts E–H into them (recommended: transcribe Parts E–H into JSON files `registry/models/*.json`, `registry/views/*.json`, `registry/actions.json`, `registry/menus.json`, `registry/seed/*.json`; a companion machine-readable export `odoo_spec.json` with the same content is supplied next to this prompt — use it to generate the JSON files instead of retyping).

```ts
type FieldType = 'char'|'text'|'html'|'integer'|'float'|'monetary'|'boolean'|'date'|'datetime'|'selection'|'many2one'|'one2many'|'many2many'|'binary'|'image'|'reference'|'many2one_reference'|'json'|'properties'|'properties_definition';
interface FieldDef { name: string; type: FieldType; label: I18n; help?: I18n; required?: boolean|Expr; readonly?: boolean|Expr; relation?: string; inverse?: string /* o2m */; selection?: {value:string; label:I18n}[]; default?: any|((ctx)=>any); compute?: string /* function name */; store?: boolean; depends?: string[]; related?: string; currencyField?: string; digits?: [number,number]; tracking?: boolean; index?: boolean; translate?: boolean; companyDependent?: boolean; domain?: Domain|Expr; groups?: string[]; copy?: boolean; ondelete?: 'cascade'|'set null'|'restrict'; sanitize?: boolean; }
interface ModelDef { name: string /* 'sale.order' */; description: I18n; table: string; recName: string /* 'name' */; order: string /* 'date_order desc, id desc' */; fields: Record<string, FieldDef>; inherits?: string[] /* mixins: mail.thread, mail.activity.mixin, utm.mixin, rating.mixin, portal.mixin, avatar.mixin, image.mixin, analytic.mixin, sequence.mixin */; delegates?: Record<string,string> /* _inherits */; sqlConstraints?: {name:string; sql:string; message:I18n}[]; access: AccessRule[]; recordRules: RecordRule[]; methods: Record<string, MethodDef>; transient?: boolean; }
interface ActionDef { id: number|string; xmlId: string; type: 'act_window'|'client'|'server'|'report'|'url'; name: I18n; model?: string; viewMode?: string[] /* order of the view switcher */; views?: [number|false, ViewType][]; domain?: Domain; context?: Record<string,any>; target?: 'current'|'new'|'fullscreen'|'main'; help?: I18nHtml; searchViewId?: number; limit?: number; path?: string /* URL slug */; tag?: string /* client action name */; params?: any; url?: string; reportName?: string; groups?: string[]; bindingModel?: string; bindingType?: 'action'|'report'; }
interface MenuDef { id: number; xmlId: string; name: I18n; parentId?: number; sequence: number; actionId?: ActionDef['id']; groups?: string[]; webIcon?: string /* app icon */; children: MenuDef[]; }
type ViewType = 'list'|'form'|'kanban'|'search'|'calendar'|'pivot'|'graph'|'gantt'|'activity'|'map'|'cohort'|'grid'|'hierarchy';
interface ViewDef { id: number; model: string; type: ViewType; arch: ViewNode /* the parsed tree exactly as in Part E */; inheritId?: number; priority?: number; }
```

**Expressions.** Odoo's `invisible`, `readonly`, `required`, `column_invisible`, `decoration-*`, `domain` and `context` attributes are Python-like expressions evaluated against the current record (`state != 'draft'`, `not partner_id`, `parent.state == 'sale'`, `context.get('hide_pdf_quote_builder')`, `context_today()`, `today`, `uid`, `allowed_company_ids`, `[('company_id','in',allowed_company_ids)]`, `product_uom_qty > 0 and not display_type`, `state in ['draft','sent']`, `commitment_date and (expected_date < commitment_date or ...)`, `'%Y-%m-%d'` strftime…). Write one **expression evaluator** (`packages/engine/expr/`) that parses this Python subset (literals, lists/tuples/dicts, `and/or/not`, comparisons incl. `in`/`not in`, arithmetic, attribute access `parent.x`, `context.get()`, `.strftime()`, `datetime`/`relativedelta` helpers, `bool()`, `len()`, `any()`, string methods) and evaluates it both **client-side** (view conditions) and **server-side** (domains, defaults, record rules). Domains are the Odoo polish-notation lists `['|', ('a','=',1), ('b','!=',False)]` with operators `= != > >= < <= like ilike not like not ilike =like =ilike in not in child_of parent_of any not any`; implement `domainToSql()` and `domainMatch(record)`.

### A-3. The ORM (server, `amplify/functions/orm/`)

Implement an `Environment` per request (`uid`, `context`, `companyIds`, `lang`, `tz`) and the following operations for every model, with **exactly** Odoo's semantics:

- `create(vals[])`, `write(ids, vals)`, `unlink(ids)`, `copy(id, defaults)` — apply defaults (`default_get`: field defaults, `default_<field>` context keys, company/currency/user defaults), compute stored computed fields (dependency graph, recompute on `depends`), run `onchange` chains, validate constraints (`required`, sql constraints, `_check_*` python constraints listed per model in Part D), write `create_date/create_uid/write_date/write_uid`, post tracking messages for `tracking=true` fields (chatter "Changed X: old → new"), fire automations/subscriptions.
- `search_read(domain, fields, offset, limit, order, context)` with `active_test` (hide `active=false` unless `active_test: False`), record rules, company filtering (`allowed_company_ids`), name display of many2one as `[id, display_name]`, one2many/many2many as id arrays, monetary formatting metadata.
- `read_group(domain, fields, groupby, lazy, orderby)` for list group-by headers, kanban columns, pivot & graph (support `date:month`, `date:week`, `date:quarter`, `date:year`, `date:day` intervals, aggregates `sum/avg/min/max/count/count_distinct/bool_and`, `__count`, `__domain`, `__fold`).
- `name_search(name, domain, operator, limit)` (used by every many2one dropdown — first 8 results, "Search More…", "Create "xxx"", "Create and edit…").
- `onchange(values, fieldNames, fieldOnchange)` — return updated values + warnings (`{warning: {title, message}}` shows a warning dialog, e.g. partner "Sale warning") + domain changes.
- `web_read` / `web_save` with **specification** (nested fields for x2many like Odoo 17+): forms load the record and its lines in one call.
- `call_button(model, ids, method, context)` → executes business methods (`action_confirm`, `action_post`, `button_cancel`…) returning either nothing (reload), an action to open (wizard `target: new`), a URL, a notification `{type:'ir.actions.client', tag:'display_notification', params:{title, message, type:'success'|'warning'|'danger', sticky}}`, or `{type:'ir.actions.act_window_close'}`.
- `toggle_active` (archive/unarchive), `action_archive`, `action_unarchive`, `export_data(fields)` (XLSX/CSV), `load(import)`, `get_formview_action`, `message_post`, `message_subscribe`, `activity_schedule`, `activity_feedback`, `activity_unlink`, `get_views(views)`, `load_action`, `load_menus`, `fields_get`.
- **Sequences** (`ir.sequence`): `next_by_code(code)` transactional (`SELECT ... FOR UPDATE`), prefix with `%(year)s`, `%(month)s`, date-range sequences (per year), padding — used for `S00001` quotations, `INV/2026/00001` invoices, `RINV/…` credit notes, `BILL/…`, `PAY/…`, `P00001` purchases, `HT00001` helpdesk?, `AR000001` approvals, `PBNK1/…` bank, `MISC/…`, etc. (see Part I `ir.sequence`).
- **Mixins** implemented once and reused: `mail.thread` (messages, followers, tracking, notifications), `mail.activity.mixin` (activities, `activity_state` planned/today/overdue, `activity_summary`, `my_activity_date_deadline`), `rating.mixin`, `utm.mixin`, `portal.mixin` (access token & share URL), `image.mixin` (image_1920 → 1024/512/256/128 variants), `avatar.mixin` (generated SVG avatar with initial letter on colored background — exactly like Odoo: square, 1 letter, hue derived from name), `analytic.mixin`, `sequence.mixin`, `html.field.history.mixin`, `properties` (custom fields per parent record, used by Project tasks / Knowledge / Helpdesk / Fleet), `resource.mixin`.
- **Access control**: groups (`res.groups`) exactly as Part I lists them; per-model CRUD access rules; record rules (e.g. "Personal Quotations: user_id = uid", "Own documents", multi-company rule `company_id in allowed_company_ids`); UI hides elements with `groups="..."`; server throws `AccessError`. Roles UI = user form "Access Rights" tab (Part E › Settings › Users).
- **Multi-company**: `res.company` records, company switcher in systray when >1 company, `company_id` on every business record, company-dependent fields (properties), per-company sequences/journals/currencies.
- **Currencies & amounts**: `res.currency` with `rounding`, `decimal_places`, `symbol`, `position`; monetary fields render with the currency of `currency_field`; multi-currency conversion with rates; `float_round`, `float_compare` semantics.
- **Dates**: store UTC; render in user tz (`Asia/Riyadh`); date formats per language (`%m/%d/%Y` en, `%d/%m/%Y` ar, 12-hour clock `%I:%M:%S %p`); relative dates in chatter ("Today", "Yesterday", "2 days ago", "Sep 11").

### A-6. Deployment & environments

- `npx ampx sandbox` for dev; branch deployments via Amplify Hosting (main → prod). Aurora in private subnets, Lambdas in VPC with RDS Proxy. Secrets via Amplify secrets (`SES_FROM`, `DB_URL`).
- Environment config UI lives inside the app (Settings › General Settings), NOT in env vars: company data, document layout, languages, outgoing mail servers (SES config exposed as `ir.mail_server` records), digest emails, developer tools.
- Seed on first deploy: Part I data + demo-free empty state (the instance we captured is empty of business documents, showing onboarding/sample-data states — reproduce those exact empty states).
