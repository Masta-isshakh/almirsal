3. **Menu sections** (`o_menu_sections`): top-level children of the app root menu rendered as text buttons (14px, padding 0 8px, hover bg); items with children open a dropdown (nested children become sub-headers with indented items exactly as the Part E navigation trees). 4. **Systray** (`o_menu_systray`, right side, items 26px): in order: **Ask AI** (AI logo image, opens the "Odoo AI" side chat window: header "Odoo AI ▾", minimize/expand/close icons, welcome block "Odoo AI — Your Odoo sidekick for most day-to-day tasks." with suggestion chips "Show me the current cash flow status", "Which projects cost us the most?", "Top 5 sales reps by revenue", input "Message Odoo AI…" with microphone icon — implement with any LLM backend, answering with data from the DB and opening actions); **Messages** (`fa-comments` + red pill counter of unread; opens the Messaging Menu C-1a); **Activities** (`fa-clock-o` + counter; opens Activities menu C-1b); **Odoo Studio** icon (`oi-studio` — in the clone: opens the Studio-like view editor in debug mode, or hide); **company switcher** (when multi-company: dropdown listing companies with checkboxes and "current company" star); **user name** text + **avatar** 26px square with online status dot → user menu (C-1c). ### C-2. Home menu (`/odoo`)

Full-screen lavender background (B-1), navbar transparent showing only the systray; yellow trial banner (when applicable) centered above the grid; grid of app tiles (icon + caption) in the order of the root menus with sequence: Discuss, Calendar, Appointments, To-do, Knowledge, Sales, Dashboards, Rental, Accounting, Documents, Project, Planning, Helpdesk, Surveys, Purchase, Sign, Employees, Attendances, Fleet, Approvals, Apps, Settings. ### C-3. Command palette (`Ctrl+K`)

Modal 500px: input "Search for a command…"; default list: contextual commands from the current view (Save ALT+S, Discard ALT+J, Search… ALT+Q, New/Create, Duplicate, Delete, Export…), global: Activity ALT+SHIFT+A, Add a To-Do ALT+SHIFT+T, Show My Activities, Show All Activities, Switch Company ALT+SHIFT+U, Ask AI, "Go to Discuss", "Toggle debug mode"; footer tip "TIP — search for /menus, @conversations and ?articles". Prefixes: `/` menus (all menu paths "App / Section / Item"), `@` users & partners (open chat), `#` channels, `?` Knowledge articles ("Advanced Search ALT+B"), `!` (debug) technical.

### C-4. Action manager, breadcrumbs, URLs

Every menu click loads an action (Part E lists them as S-numbers). URL `/odoo/<path>` where `path` is the action's slug (e.g. `/odoo/sales`, `/odoo/orders`, `/odoo/customer-invoices`, `/odoo/discuss`, `/odoo/knowledge/32`, `/odoo/documents`, `/odoo/planning`, `/odoo/attendances`, `/odoo/accounting`, `/odoo/balance-sheet`, `/odoo/profit-and-loss`, `/odoo/settings`, `/odoo/apps`, `/odoo/users`, `/odoo/companies`); actions without a slug use `/odoo/action-<id>`; record: `/odoo/orders/12`, new: `/odoo/orders/new`; view type `?view_type=kanban`; nested breadcrumbs: `/odoo/orders/12/action-448` etc. Breadcrumb shows parents as teal links, current as text; when the stack gets long, older crumbs collapse into "…" (Sign template form shows "… / Sample Contract.pdf"). Browser back/forward navigate the stack. Dialogs (`target: new`) don't change URL.

### C-5. Generic record features available on every model with chatter (`mail.thread`)

Messages/notes/activities/followers/attachments (A-4 §17); "Send message" sends email to followers (with the email template of the model when defined: e.g. "Sales: Send Quotation" template with PDF attached); tracking of changes; activity plans ("Schedule activity plan" from the chatter: applies a list of activities, e.g. onboarding plans); rating emails; portal share; "Print" menu PDFs; "Export"; import; archive; duplicate; delete; keyboard navigation between records; "Discard changes" guard; auto-save; concurrent-edit warning ("The record has been modified, your changes will be discarded…"); required-field validation (red underline + "Invalid fields:" dialog listing labels); onchange warnings; access error dialogs; record rules.

### C-6. Settings page (`res.config.settings`) behaviour

One page for all apps (Part F): left sidebar app list (icon + name; active = teal text) scrolls the content to the app block; "Save" applies all values (`execute` re-installs modules for `module_*` toggles, creates related records), "Discard" reloads; search box filters settings live (non-matching blocks hidden, matches highlighted); each `SETTING` renders as a 2-column responsive card: left checkbox/toggle (when the first field is boolean) + bold label + help text + "documentation ↗" link when `documentation` attr, then dependent fields appear indented when enabled (`invisible` conditions); `company_dependent` shows a building icon; `groups` restrictions hide the setting; `type="header"` settings render as section headers with a company selector. Buttons inside settings (`→ Manage Users`, `→ Add Languages`, `Invite` button with email input, `→ Configure document layout`, `→ Update` etc.) open the actions listed in Part F. Hash anchors `#sale_management`, `#discuss_setting`, `#account`… select the app block.

### C-7. Login, signup, password reset, invitations, sessions

See B-10. Invitation flow: Settings › Users › Invite → email with "Set password" link. Session expiry → "Your session expired" dialog → re-login keeps the URL. Passkeys (WebAuthn) via Cognito or custom. 2FA (TOTP) in My Preferences › Account Security with QR. API keys page ("New API key" with scope + description → shows key once). "Log out" → `/web/login`. Kiosk URLs (attendance) are public token URLs. Portal share links (`/my/orders/<id>?access_token=`) render a customer portal (quotation accept & sign & pay page, invoice view/pay, helpdesk ticket, project task, sign document signing page, survey answering page, appointment booking page, calendar invite accept/decline page) — implement these public pages with Odoo's portal look (white cards on light grey, company header).
